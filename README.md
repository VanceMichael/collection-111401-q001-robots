# 采集队列中的站点访问政策执行

提供公开馆藏入口、访问公告和原文收件。采集入口内置访问政策管理：新发现和已经排队的链接，都在每次派发时按当前有效政策判断，每次领取或暂停都会记录所依据的公告版本。

## 运行

使用 Node.js 22。依赖版本已锁定，运行、测试和演示不下载任何数据或软件。运行时只使用 Node.js 内置模块。

- `npm test`：执行本地来源交互、访问政策及收件存储测试。
- `npm run build`：逐个检查模块语法。
- `npm run demo`：启动本地来源，运行批量采集与政策演练（临时关闭、恢复开放、公告不可达），打印每阶段结果后退出。
- `npm start`：在 127.0.0.1:8080 启动本地来源，PORT 可调整。`GET /health` 返回服务与当前来源版本；原有 `/_health` 仍可使用。

容器方式：`docker build -t collection-robots .`，然后 `docker run --rm --network none collection-robots`。镜像构建属于环境准备，运行时不访问公网。

## 项目结构

`src/domain.mjs` 提供业务入口：`receiveCurrent` 领取入口公告页，`collect` 批量采集（发现链接、排队、按政策派发），`createCollection` 组装采集上下文。`src/policy.mjs` 按来源获取、缓存并评估 robots 公告（RFC 9309）。`src/collection.mjs` 维护采集队列和决定日志。`src/client.mjs` 负责人工指定地址的有限大小原始领取；`src/archive.mjs` 保存内容及来源凭据。`provider/` 是独立的本地来源服务，`docs/source-contract.md` 说明它的资料和状态约定。演示使用临时目录，正式接入可向业务入口传入持久目录。

## 访问政策执行

- 每个来源的公告独立获取和缓存，判断不跨来源串用；版本取响应 ETag，缺失时取内容摘要。
- User-agent 只匹配最具体的一组（采集身份 `CollectionBot`），其他分组的规则不串用；路径比较前按 RFC 9309 归一化：非保留字符的百分号编码解码、其余编码的十六进制统一大写，编码后的路径既不串用其他路径的判断，也不能借编码绕过限制。不支持的扩展字段不作为授权依据。
- 每次领取或暂停都写入 `<收件目录>/decisions.jsonl`，包含所依据的公告版本与命中的规则；收件凭据的 source 也带政策版本。
- 公告 5xx 或超时不可达：缓存仍在有效期则沿用；超出有效期进入等待确认（暂停），不当作没有限制。404 表示没有公告，但不扩张来源白名单。
- 暂停的资料保留在队列中，馆方恢复开放后再次执行 `collect` 即继续领取，不会永久丢弃。
- 授权以来源白名单为上界（默认仅入口来源本身）；被禁止的路径不请求、不探测。

本地服务中的机构、记录和文件都是合成业务资料，不使用真实账号、个人信息或第三方站点数据。当前演示通常十秒内结束，全部本地测试应在六十秒内结束。
